## 一面（技术面）

### 1. vLLM 的 PagedAttention 原理？
- KV Cache 按 block 分配，类似 OS 虚拟内存
- 逻辑地址 → 物理 block 的映射表
- 消除碎片，显存利用率从 ~60% → ~95%

### 2. Tensor Parallel 列切 vs 行切的区别？
- **列切**（ColumnParallel）：W 按列切，输出按最后一维分块，需 all-reduce
- **行切**（RowParallel）：W 按行切，输入按最后一维分块，输出直接 all-reduce
- Megatron 的 QKV 用列切，FFN up 用列切，FFN down 用行切

### 3. 混合精度训练中 loss scale 的作用？
- FP16 梯度可能下溢（< 2^-24）
- loss scale：前向乘 S，反向梯度也乘 S，更新前除 S
- 动态 loss scale：溢出时减半，连续 N 步不溢出时翻倍

### 4. 手撕：实现一个简单的 KV Cache
```python
class KVCache:
    def __init__(self, n_layers, n_heads, d_head, max_len, dtype=torch.float16):
        self.cache = [torch.zeros(max_len, n_heads, d_head, dtype=dtype) for _ in range(n_layers * 2)]
        self.pos = 0
    def append(self, k, v):
        for layer in range(len(k)):
            self.cache[layer * 2][self.pos] = k[layer]
            self.cache[layer * 2 + 1][self.pos] = v[layer]
        self.pos += 1
    def get(self, layer):
        return self.cache[layer * 2][:self.pos], self.cache[layer * 2 + 1][:self.pos]
```

## 二面（系统设计面）

### 5. 设计一个支持多 LoRA 适配器的推理服务
- **共享 base model**：base model 常驻显存
- **LoRA 热加载**：A/B 矩阵小，按需 swap
- **Batch 调度**：不同请求可用不同 LoRA，需在 batch 内区分
- **vLLM LoRA**：支持多 LoRA 并发，通过 `lora_name` 路由

### 6. 推理服务 QPS 优化思路
1. Continuous batching（动态拼 batch）
2. Prefix caching（共享 system prompt 的 KV Cache）
3. Speculative decoding（draft model 加速）
4. 量化（W8A8 / W4A16 降显存提吞吐）
5. Tensor Parallel（大模型拆多卡）
