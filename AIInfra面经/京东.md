# 京东 AI Infra 面经

## 一面（技术面）

### 1. ZeRO 三个阶段的显存节省？
| 阶段 | 切分内容 | 显存（每卡） | 通信 |
|------|----------|-------------|------|
| ZeRO-1 | Optimizer State | 4C + 2ψ | reduce_scatter |
| ZeRO-2 | + Gradient | 2C + 2ψ | reduce_scatter |
| ZeRO-3 | + Parameter | 4C + 2ψ/N | all_gather + reduce_scatter |

- C = 模型参数量，ψ = 梯度大小，N = GPU 数

### 2. Pipeline Parallel 的 1F1B 调度？
- 相比 GPipe（所有前向后所有反向），1F1B 交错执行
- 优势：激活值显存从 O(N_stage) 降到 O(1)
- Interleaved 1F1B：每个 stage 持有多个 chunk，进一步降 bubble

### 3. FlashAttention 为什么快？
1. **IO-aware**：分块计算，SRAM 中完成 softmax，减少 HBM 读写
2. **Online softmax**：无需实例化完整 N×N attention matrix
3. **Kernel fusion**：QK^T → softmax → AV 融合为一个 kernel
4. **反向也快**：重算前向（存 logits 而非 attention matrix）

## 二面（系统设计面）

### 5. 设计一个 MoE 训练系统
- **Expert Parallel**：每 GPU 持有部分专家，All-to-All 通信
- **负载均衡**：auxiliary loss 防止专家不均
- **Top-K Router**：每 token 选 2 个专家
- **Capacity Factor**：每专家最大处理 token 数，超限丢弃
- **通信优化**：All-to-All overlap 计算，grouped GEMM

### 6. 大模型训练 OOM 排查思路
1. `torch.cuda.memory_summary()` 看分配详情
2. 检查激活值大小（用 activation checkpointing）
3. 检查梯度累积是否正确
4. 检查 ZeRO 阶段是否够高
5. 检查混合精度是否开启
6. 检查 optimizer state（8bit optimizer）

## 三面（主管面）

### 7. 对比 DDP 和 ZeRO-3 的通信量
- DDP：每步 all-reduce 梯度，通信量 = 2ψ × (N-1)/N
- ZeRO-3：前向 all-gather 参数 + 反向 all-gather 参数 + reduce_scatter 梯度
- ZeRO-3 通信量 ≈ 3× DDP，但显存从 O(ψ) 降到 O(ψ/N)
- 结论：ZeRO-3 用 1.5× 通信换 N× 显存
